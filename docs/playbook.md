# 日常使用

## 新功能

“读取项目入口、Product Spine 和当前任务源。判断 Quick/Standard/High-risk，明确范围和验收证据，
只在信息缺失时澄清，完成授权范围内的实现与检查。Standard/High-risk 交给独立上下文 Review。”

## 修 Bug

“先复现这个症状并找第一手证据，明确根因和影响范围，再做最小修复；能够稳定复现时增加回归测试。
不要把原因不明的故障解释成环境问题。记录原症状是否消失和受影响行为是否回归。”

## Review

“按任务契约审查这份 diff，包括未提交的新文件。读取已有验证证据，重点寻找行为错误、契约遗漏和范围扩张。
每项发现说明触发条件、实际影响和证据，区分阻塞项与建议。不要替实现者自动扩大功能。”

## 换会话

读取 `.spine/config.json` 指定的 context 文件、任务源和实际 Git 状态。
context 只指向当前任务、分支、下一步与阻塞；不能替代任务详情。发现不一致以实际文件/Git和有证据任务记录校正。
结束时用 handoff 或等效操作更新此指针，不另建一份长期“最新状态”文档。

## 发布

验收任务范围与代码快照，再检查独立 Review 和部署前置条件；依据用户授权发布。
记录发布版本、验证和恢复路径。任务 Done 不自动授权 merge/deploy。

## 复盘

仅在出现值得复用的经验时记录：问题、原因、证据、预防机制和适用范围。
能转成测试或检查的优先转；无需每个任务新增规则。评估通用性后提交 feedback。
