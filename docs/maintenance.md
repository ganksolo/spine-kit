# 规范更新、旧版迁移与维护

VERSION 标识规范版本，实际 Git commit 标识读取的内容。记录能核实的值；不可获得时写 unknown。
0.x 的不兼容变化写明在 CHANGELOG；版本文件不代表已有同名 Git tag。
项目只在明确需要时读取新版比较差异，不要求持续同步或每次开工联网。

## 更新一个使用方项目

1. 读取项目原适配记录、当前指引、实际 Git 状态，找出上次参考版本与项目例外。
2. 比较旧规范、新规范与项目现有规则；旧参考不可用时说明限制，逐项核对，不能假装完成三方比较。
3. 说明采用/保留/延后哪些变化。只把适用变化合并到项目文件，不覆盖全部指引或历史任务。
4. 按 ADOPT 核对入口、单一任务源、工具状态与典型任务路径。
5. 在已有适配记录追加更新日期、来源、改动、证据、例外和未完成项。

第三方技能版本独立记录；其自动更新不能被当作项目规则兼容保证。

## 从 0.1.x 迁移到 0.2.0

0.1.x 要求 `.spine/config.json`、vendor 快照、setup/verify/finalize 脚本；0.2.0 取消这些依赖。
这些旧实现保留在 Git 历史中，不再是当前适配协议。不要直接删除目标项目的 `.spine`：

1. 盘点旧配置中的路径、检查命令、工具选择，以及旧目录内实际是否有用户修改或有效证据。
2. 把必要规则和命令整理进目标项目自己的 WORKFLOW/现有文档，让 AGENTS/CLAUDE 引用实际本地位置。
3. 将来源版本、旧日志/证据位置、项目例外和剩余项整理进适配记录；历史可归档并保持引用可追溯。
4. 查找 CI/hooks/其他文件对旧脚本和目录的引用，改为项目原生检查入口；逐项核对替换是否有效。
5. 确认无活跃依赖、必要证据已保留后，在用户授权范围内移除旧生成物；否则保留为明确的历史归档。

源仓库删除旧脚本不会自动迁移任何使用方项目。没有真实使用方迁移证据时不得声称已迁移完成。

## 撤销与中断恢复

适配前记录 Git 状态；每步记录改动文件和结果。恢复时对照记录与实际 diff，只撤销本轮修改。
不 reset 工作区、不清理未知未跟踪文件、不删除仍被引用的历史。
无 Git 项目在修改前保留现有文件备份并记录位置；不要制造不可恢复的全量覆盖。

## 防止文档再次膨胀

一个事实一个位置：产品边界在 Spine；任务状态在 Trellis/已选任务源；短接续指针指向任务；历史在 Journal；重大稳定决定在 ADR。
适配记录只记录流程配置过程，不承载日常业务任务状态。入口文件只放稳定规则和本地链接。
按需归档历史、保留索引；没有可复用教训就不加规则。

## 本仓库维护核对

检查内部链接、模板路径说明、术语一致性与新旧项目走查；检查无密钥或私有业务数据。
规范改动记录版本与迁移影响。独立 Review、实际工具集成和真实业务项目试点单独报告，不能由文档检查替代。
