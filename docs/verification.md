# 证据与完成标准

每条验收条件绑定：方法、预期、实际结果、输入/fixture、代码版本或工作区指纹、证据位置、局限。
检查项不能是“看起来正常”；外部数据与模型输出尤其需要验证实际含义。

机器检查、独立 Review、真实验收分别记录。未跑写 not-run，有原因；不能把 skip 写成 pass。
已有基线失败应与新增回归分开解释，不得静默删除失败或声称全绿。
代码或验证输入变化后判断哪些旧证据失效；同一快照无变化时不要无意义重复检查。

Review 关注：任务匹配、产品边界、契约变化、错误/中断路径、依赖、测试遗漏和不必要复杂度。
发现需指出触发条件、影响、证据和修复要求；建议不自动成为阻塞项。
报告通过不意味着“没有 bug”，应列未覆盖范围。Review 自查不能冒充独立审查。

## 对 Agent/数据类项目的可选补充

验证事实来源、日期/单位、缺失值语义、上下游真正消费输入、异常分层和真实样本。
自报状态不是独立事实验证；模拟数据覆盖不代表真实接口可靠；网络成功不代表业务数据正确。
这些检查仅在相关项目启用，不能全局要求每个 Web 文案修改做数据源审计。

## Product Path Gate

- 强化项目核心用户路径，验收结果实际有用？
- Objective 与 diff 一致，无隐藏范围扩张？
- 项目 non-goals / API / data 合约是否保持或经过明确决策？
- 关键交接、失败路径和真实场景有证据？
- 完成、合并、上线和剩余风险分别记录？
- 是否需要更新稳定规范，还是只需任务记录？

输出 PASS / FAIL / NOT-READY，加阻塞项、证据和局限。NOT-READY 不能标 Done。
