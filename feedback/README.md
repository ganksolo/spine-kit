# 实践反馈与改进循环

项目发现问题 → 记录最小案例 → 判断通用性 → 改进与测试 → 发布版本 → 项目自主升级。

使用 [反馈模板](../templates/feedback.md)，可在本仓库开 issue 或提交脱敏案例。
不要自动上传项目源代码、客户数据、完整会话、密钥或私有路径。

分类：
- 通用规则缺陷：进入规范、模板或项目自动化建议修正。
- 仅某技术栈有效：进入可选适配示例。
- 仅单个项目成立：留在业务项目，不升级为所有项目硬约束。
- 工具 bug：记录版本，向相关上游报告；本仓库只保留必要 workaround 和移除条件。

评估收益：人工介入时间、验收后重开次数、同类缺陷复发、完成到发布的时间。
Review 轮次、token 数和文档行数可辅助诊断，不能单独代表质量。
一次只试少量变化，连续 5–10 个任务观察；允许撤回增加负担而无收益的规则。

## 谁执行回流

项目 Agent 在复盘中先形成脱敏建议，写回项目已有任务/Journal；仅在用户授权后向本仓库提交 issue/改动。
维护者根据案例和反例决定采纳、延后或保留为项目特例，再更新规范版本。
使用方读取新版时依据原适配记录比较，只采用适合自己的变化，不被自动重写。
